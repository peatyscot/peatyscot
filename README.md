# peaty.scot

A richly interlinked reference for exploring the whiskies of the world — distilleries,
regions, flavour profiles, and eventually a page per bottle SKU.

Static site generated by [Hugo](https://gohugo.io), served from
[Cloudflare Workers](https://developers.cloudflare.com/workers/static-assets/) at
<https://peaty.scot>.

## Why this stack

The site is fundamentally "render structured data to HTML, densely cross-linked." Hugo
does the boring 60% of that — taxonomies, pagination, sitemaps, RSS, SCSS, image
processing, asset fingerprinting — battle-tested and for free.

A custom generator was considered and rejected: it would have been ~1500–2500 lines of
plumbing to own forever. Astro and Eleventy were rejected because their content-model
opinions fight a custom backlink graph, and neither matches Hugo's build throughput at
SKU scale.

Measured on this project's own spike (Hugo v0.159 extended):

| Property | Result |
|---|---|
| 5,032 pages, taxonomies + related + full backlink graph | **7.9 s**, 300 MB RSS |
| Broken internal ref | build **fails**, exit 1, `file:line:col` |
| Sitemap, taxonomy term pages | generated, no code |

One trap found and avoided: computing backlinks by scanning every page for every page is
O(n²) and **exceeded 120 s at 5,000 pages**. Building the index once into a `newScratch`
behind `partialCached` brings the same work to 7.9 s. See
`layouts/partials/backlink-index.html`.

Hugo does not do two things this project needs, so a thin Node layer covers them:

- **Schema validation.** Hugo will happily build `abv: fourty`, or a bottling naming a
  distillery that does not exist. `tools/validate` enforces the content schema.
- **Bulk SKU generation.** When retailer/affiliate feeds land, a script emits Markdown
  that Hugo renders. Generated pages are committed, so they show up as reviewable diffs.

## Layout

```
content/        entity pages (Markdown + YAML front matter) — the source of truth
layouts/        Hugo templates
assets/         SCSS and JS, processed by Hugo Pipes
static/         files copied verbatim (robots.txt, ads.txt)
tools/validate/ Zod schema validation over front matter
public/         build output (gitignored)
```

## URL structure

Flat, trailing-slash, apex-only (`www` redirects to apex). Country and region are separate
dimensions so a Japanese distillery is not forced into a fake "region".

```
/countries/scotland/          /regions/islay/        /distilleries/lagavulin/
/whiskies/lagavulin-16-year-old/                     /flavours/peat-smoke/
/glossary/phenol-ppm/         /guides/what-makes-a-whisky-peaty/        /explore/
```

These are permanent. Changing them later means redirects and lost rankings.

## Interlinking

The wiki character of the site is enforced, not hoped for:

- Internal links use `relref`, so **a broken link fails the build**.
- Every page renders a *What links here* section from the computed backlink index.
- Typed relations are automatic: distillery → its bottlings and region; bottling →
  distillery, region, and nearest neighbours by shared flavour tags.
- Build lints reject orphan pages, duplicate slugs, missing meta descriptions, missing
  citations, and pages with fewer than five outbound internal links.

## Content integrity

Structured facts come from **Wikidata (CC0)**, which is safe to import directly.
Wikipedia and official distillery sites are research leads only — all prose is written
fresh, and every page renders a `sources:` block with title, URL, and access date.

Tasting notes are **synthesized from cited published notes and labelled as aggregated**.
No invented first-person reviews: the site never claims a tasting experience it did not
have.

## Commands

```sh
npm run validate    # schema + referential integrity over content/
npm run dev         # hugo server -D, live reload
npm run build       # validate, then hugo --minify into public/
npm run check       # build + offline link check over public/
npm run deploy      # check, then wrangler deploy
```

## Monetization

Ad slots are **built but inert**. Containers reserve fixed height so enabling ads causes
zero layout shift; in-article and sidebar only, maximum two per page, never above the
fold, no vignettes or interstitials. Enabling them is a config change plus a publisher ID.

Two prerequisites before ads can serve:

1. A privacy policy (written, at `/about/privacy/`) — required by AdSense.
2. A Google-certified consent CMP — required to serve EEA/UK traffic.

Affiliate offers are a first-class schema field, empty until affiliate approval. Note that
Amazon Associates, Awin, and The Whisky Exchange all review a live site with real content
before approving, so this necessarily follows launch rather than preceding it.

## Compliance

No hard age gate — it blocks crawlers and would kneecap indexing. Instead: a dismissible
age-affirmation banner, a footer responsible-drinking notice, and
`/about/responsible-drinking/`.

## Roadmap
